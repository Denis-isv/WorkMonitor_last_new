# Матрица реализации WorkMonitor относительно ТЗ

Статус описывает именно этот архив. «Основа» означает, что есть модель/API/ручной экран, но автоматический промышленный процесс ещё не завершён.

## Реализовано в проекте

- [x] Авторизация и роли `admin`, `manager`, `project_manager`, `employee`.
- [x] Календарь: месяц / неделя / день, фильтры, CRUD событий. Внешний вид календаря и исходные CSS-стили сохранены.
- [x] Сотрудники, подразделения, рабочие графики и код привязки Telegram.
- [x] Проекты и задачи со статусами, ответственными, приоритетами и сроками.
- [x] Ручной учёт трудозатрат: дата, длительность, точность, источник, confidence, статус подтверждения.
- [x] Ручные события СКУД (вход/выход), корректировки и API расчёта присутствия, опоздания, раннего ухода и потенциальной переработки.
- [x] Реестры решений, проблем/блокировок, результатов и смысловых блоков.
- [x] Хранение исходных Telegram-сообщений и вложений polling-ботом; защита от дублей по chat ID + message ID.
- [x] Опциональная локальная транскрибация faster-whisper, если зависимость установлена и `WHISPER_ENABLED=true`.
- [x] Опциональный LLM-парсер через OpenAI-совместимый endpoint; порог авто-принятия настраивается `AI_AUTO_ACCEPT_THRESHOLD`.
- [x] AI-события с confidence, статусом, ссылкой на ID исходного сообщения и журналом запусков LLM.
- [x] Реестр AI-событий, требующих подтверждения; можно изменить статус вручную в интерфейсе.
- [x] Отчёт по трудозатратам за произвольный период, распределение по проектам, CSV-экспорт.
- [x] Журнал действий для основных операций, health endpoint и API поиска по тексту.
- [x] Безопасная конфигурация без включённых по умолчанию облачного AI и токена Telegram; генерация случайного пароля администратора при первом запуске из шаблона.

## Частично реализовано / требует настройки

- [ ] Полная автоматическая сборка `DiscussionBlock` из цепочек сообщений, веток ответов и временных окон.
- [ ] Сквозной AI-процессинг всей переписки в фоновой очереди, ретраи, версионирование prompt/модели и повторный анализ старых сообщений из интерфейса.
- [ ] Автоматическое связывание AI-событий с существующими проектами и задачами, объединение смысловых дублей и полная трассируемость из каждого события до оригинала в UI.
- [ ] Уведомления с inline-кнопками «Подтвердить / Изменить / Не учитывать» и планировщик вечерних/недельных сообщений.
- [ ] Реальная интеграция с конкретной СКУД. Сейчас есть универсальная модель, ручной ввод и расчётная API; формат производителя/импорт нужно согласовать.
- [ ] Полный производственный календарь РФ, праздники, переносы, сменные и индивидуальные графики, исключения по датам.
- [ ] Семантический RAG/embeddings и pgvector. Текущий `/api/search` — текстовый поиск, не векторный поиск.
- [ ] Полный RBAC по подразделениям и проектам, HTTPS, резервное копирование, rate limiting, полноценные миграции Alembic и эксплуатационный мониторинг.

## Примечания

- Нераспределённое время не интерпретируется как безделье или нарушение.
- Предположения LLM не следует использовать как кадровые факты без проверки.
- Архив намеренно не содержит `.env`, токенов, ключей, виртуального окружения или базы данных пользователя. При первом запуске создаётся новая локальная база.
- Перед реальной эксплуатацией на данных сотрудников нужно проверить правовые основания, уведомление сотрудников, сроки хранения и доступ к переписке.


## Доработка интерфейса команды (версия 2)

Добавлено в текущем архиве:
- заявка на отпуск / больничный / выходной с согласованием администратора; согласованные отсутствия появляются в календаре;
- индивидуальное расписание на ближайшие 14 дней, просмотр общего расписания команды на неделю;
- страница «Кто работает сегодня»;
- сводка месяца по каждому сотруднику: дни и часы по введённому графику, дни отпуска и больничного;
- поиск сотрудников без учёта регистра, в том числе по одному символу;
- ставка сотрудника «Полная ставка / Полставки»;
- выбор нескольких участников проекта;
- задачи с назначенным исполнителем и сроком отображаются в календаре как записи только для просмотра;
- календарь ограничен типами «Работа», «Отпуск», «Больничный», «Выходной», удалён фильтр курсов;
- для сотрудников запрещено управление учётными записями; роли в интерфейсе — администратор и сотрудник;
- бот получил меню с кнопками для расписания, команды, месячной сводки и инструкции по заявке на отсутствие.

Важные границы текущей реализации: месячная сводка рассчитывает часы по расписанию, введённому сотрудником, а не фактическое присутствие по СКУД; бот создаёт заявки на отсутствие по текстовой команде с датами, но полноценный диалоговый календарный выбор в Telegram ещё не реализован; надёжное автоматическое разнесение AI-событий, RAG/pgvector и промышленная интеграция с СКУД по-прежнему требуют отдельной работы.
